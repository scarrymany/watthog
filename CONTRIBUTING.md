# Как помочь проекту

Спасибо за интерес. Больше всего WattHog нужны три вещи, и все они не требуют
глубокого погружения в код.

## 1. Замеры с настоящим ваттметром

Самый ценный вклад. Если у вас есть розеточный ваттметр, запустите замер и
[пришлите расхождение](https://github.com/scarrymany/watthog/issues/new?template=accuracy_report.yml).
Каждый такой отчёт напрямую подстраивает модель.

```bash
watthog run --json report.json
```

К отчёту приложите вывод `watthog info`, показания ваттметра и модель блока питания.

## 2. Справочник мощности железа

Таблицы лежат в [`watthog/tdp_tables.py`](watthog/tdp_tables.py). В них хранится не
паспортный TDP, а реальная мощность под нагрузкой и в простое: у AMD и Intel паспортные
цифры считаются по-разному и напрямую в модель не годятся.

```python
("ryzen 7 7800x3d", 88.0, 24.0),
#  образец имени    пик   простой
```

Правила:

- Значения берутся из независимых замеров, а не из маркетинговых материалов.
  Годятся TechPowerUp, AnandTech, Tom's Hardware, ComputerBase.
- Образец имени пишется в нижнем регистре и сравнивается с нормализованным именем,
  из которого убраны `(R)`, `(TM)`, `CPU`, `Processor`, частота и число ядер.
- Более длинный образец имеет приоритет автоматически, поэтому `ryzen 9 7950x3d`
  не перепутается с `ryzen 9 7950x`.
- В пул-реквесте укажите источник цифр.

## 3. Проверка на редком железе

Особенно интересны ноутбуки, мини-ПК, системы на видеокартах AMD и Intel, старые
платформы. Достаточно прислать вывод `watthog info` и `watthog run --plain -d 30`.

## Работа с кодом

```bash
git clone https://github.com/scarrymany/watthog.git
cd watthog
pip install -e ".[dev]"
python -m pytest
```

### Что стоит знать про устройство

| Модуль | За что отвечает |
|---|---|
| `winapi.py` | Счётчики PDH и состояние батареи в Windows |
| `linuxapi.py` | RAPL, hwmon видеокарт и батарея через sysfs |
| `nvml.py` | Телеметрия видеокарт NVIDIA, общая для обеих платформ |
| `inventory.py` | Определение состава железа и его энергетического профиля |
| `telemetry.py` | Единый срез телеметрии поверх всех источников |
| `meter.py` | Модель мощности: срез телеметрии превращается в ватты по компонентам |
| `session.py` | Цикл замера, интегрирование энергии, статистика |
| `ui/` | Живая панель, отчёт, меню |

### Требования к изменениям

- Все числа модели живут в `constants.py` или `tdp_tables.py`, а не в коде логики.
- Новый источник телеметрии не должен ронять программу на машине, где его нет:
  недоступный источник возвращает `None`, а вызывающий код мягко деградирует до модели.
- На новую логику нужен тест. Тесты не должны требовать конкретного железа.
- Комментарии объясняют, почему сделано так, а не что делает строчка.
- Никаких длинных тире в коде, комментариях и документации - только обычный дефис.

### Перед пул-реквестом

```bash
python -m pytest
python -m watthog run -d 10 --plain --no-save
```
